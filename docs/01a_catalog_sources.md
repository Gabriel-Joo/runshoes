#### 1. 최종 설계

#### 1-1. 범위 — 무엇을 넣나

- **후보 목록** `catalog/candidates.csv` — 세대마다 한 행. 407행 · 라인 232 · 현행 232 · 브랜드 14(2026-11-03 기준, 파일을 세어서).
- **현행 = 국내에서 팔리는 가장 새 세대**(2026-11-01 사용자). 글로벌에 신형이 나와도 국내 미출시면 넣지 않는다(린콘 5 → 린콘 4 가 현행, 엔돌핀 스피드 6 → 5 가 현행).
- **라인마다 현행 + 직전 1세대.** 2세대 전은 넣지 않는다. 예외는 리뷰가 붙은 시드(엔돌핀 스피드 4)뿐 — 지우지 않는다. 직전 세대가 세대 번호로 이어지지 않는 라인은 현행만 둔다(울트라부스트 5 — 직전은 번호 없는 울트라부스트 라이트, 3절).
- **한 행 = 브랜드 + 라인 + 세대(+ 성별).** 폭(2E · 4E) · 색상 · 품번 차이는 한 행으로 합친다. GTX · 아동 · 콜라보 · 특별판은 넣지 않는다. 스펙이 다른 파생(페가수스 트레일)은 다른 라인이다.
- **남성 기준.** 여성 행은 보류한다 — 여성 스택 · 드롭이 허용 출처에 거의 없고, 남성 값을 빌려 오지 않는다.
- **적재 조건**(`build.mjs` — 상태 `ok` · `partial` 만 운영에 간다):
  - 무게 · 드롭 · 힐 스택 중 2개 이상, 이미지 1장 이상, 값마다 출처 URL
  - 비어도 막지 않는 칸: 발볼 · 와이드 · 카본 · 정가
  - 범위 밖(무게 80~400g · 드롭 0~14mm · 스택 10~65mm · 정가 1만~60만 원)이면 `review`
  - 지금: `ok` 86 · `partial` 215 · `review` 82 · `failed` 24(`shoes.jsonl` 407행, 2026-11-03)

#### 1-3. 무게

- **US M9 기준**이다. 값은 `official_weight_g`, 기준 사이즈는 `official_weight_size`(M9 · M10 · M9.5 …, 출처가 밝히지 않으면 null). 운영: M9 168 · 사이즈 불명 71 · M10 35 · M9.5 13 · M10.5 8 · M8.5 7.
- oz 만 있으면 ×28.35 반올림. 남성 UK 표기는 +1 해서 US 라벨로 적는다(UK8 = M9) — 같은 사이즈의 다른 이름이라 g 값은 그대로다.
- **우선순위**: M9 로 확인된 값 → 다른 사이즈로 밝힌 값 → 사이즈 불명, 각 묶음 안에서 국내 공식몰 · 보도자료 → BITR 스펙 상자 → fit2run → RSG 상자 → BITR 본문 → RSG 본문(`fill.mjs`).
- **작은 차이는 자동으로 고른다**: 두 기록이 무게만 5g 또는 2% 이내로 다르면 위 순서로 고르고 진 값은 `weight_notes` 에 남긴다(`build.mjs smallWeightGap · weightRank`).
- **자기모순인 출처는 쓰지 않는다**(같은 글에서 g 와 oz 가 안 맞으면). **사이즈 기준을 확인할 수 없는 큰 차이는 비운다.**
- 실측값은 공시값과 따로 둔다(`measured_*`) — 사람이 적은 것만.

#### 1-4. 드롭 · 스택 · 미드솔 · 카본

- 드롭 · 스택은 **제조사 발표값**이다. 기준 사이즈는 대부분 밝히지 않아 null 로 두고, 사이즈로 보정하지 않는다. 포어풋 스택은 두지 않는다(힐 − 드롭) — 셋 다 적힌 출처면 맞는지(±0.5) 본다.
- 출처끼리 0.5mm 라도 다르면 사람이 본다(무게와 달리 자동으로 고르지 않는다).
- 미드솔은 브랜드 상표의 영문 원문(FF Blast Plus · ZoomX). 스펙 상자에서 읽지 않는다(BITR Key Features 는 자유 문장).
- 카본은 예/아니오라 출처 URL 을 요구하지 않는다(모델 · 용도로 거의 정해진다). 비어도 적재를 막지 않는다.
- **다른 판 · 다른 모델 · 모음 글은 어느 칸에도 쓰지 않는다**(`variant.mjs`) — 주소에 라인 이름에 없는 변형 낱말(GRVL · GTX · Hike · Mid · Max · Trail …)이 있거나 `best-…` · `…-vs-…` 글이면 다른 신발이다.

#### 1-5. 가격 — 발매가(정가)만

- **할인가 · 최저가 · 쿠폰가는 어디서도 쓰지 않는다.** 출처 순서는 국내 공식몰 → ABC마트(상품 페이지 메인 표시가) → 크림(발매가 표기) → MAN(직접 확인 — 공식몰에서 내려간 모델을 관리자가 다른 자료로 확인한 발매가).
- **가격 출처는 발매가를 확인할 수 있는 곳이다** — 공식몰 · ABC마트 · 크림, 그리고 관리자가 직접 확인한 MAN. 크림은 리셀 플랫폼이지만 상품 페이지에 발매가가 표시된다 — 거래가가 아니라 그 발매가를 쓴다(브랜드가 정한 값이라 판매처 가격과 같다). 리뷰 · 영상 · 기사에 나온 가격은 쓰지 않는다(2026-11-02 사용자).
- 메타 셋을 같이 둔다(V5): `price_source` · `price_checked_at`(읽은 날) · `price_kind`(늘 `발매가`).
- 시드 20켤레 중 ABC · 공식몰에 없는 것은 사용자가 다나와에서 넣은 값을 `다나와` 로 표시해 둔다(6켤레).
- 운영: 공식몰 75 · 크림 41 · ABC마트 25 · 다나와 6 · MAN 1 · **빈 칸 154.**

#### 1-6. 발볼(토박스 너비)

- 발볼은 **토박스 너비**만 뜻한다(V4 `toebox_width`) — 미드풋은 끈으로 조절되고, 힐은 발볼과 무관하다.
- 근거로 쓰는 곳:

  | 출처 | 근거로 쓰는 조건 | 출처 코드 |
  |---|---|---|
  | BITR · RSG 리뷰 | 그 모델 · 세대의 토박스 서술 문장 | BITR · RSG |
  | 웹 검색 | 브랜드 1곳 · 비실측 2곳 | WEB |
  | **영상 리뷰(유튜브)** | 리뷰어가 그 모델 · 세대를 **직접 신어 보고** 토박스를 말한 영상(2026-11-02 사용자 — 러닝화 리뷰는 영상으로 하는 사람이 많고, 신어 보고 말하는 것이라 글 리뷰와 다르지 않다) | MAN + 영상 주소 |

  - **영상 리뷰는 발볼에만 쓴다.** 다른 칸, 특히 가격의 근거로는 쓰지 않는다(1-5).

- **자동 판정은 하지 않는다.** 후보 문장을 사람이 보는 승인 목록(`catalog/local/width*.csv`)에 올리고, 승인한 것만 `decisions.json` 에 넣는다.
- 운영: 넓음 57 · 좁음 44 · 보통 10 · **빈 칸 191.**

#### 2. 왜 이렇게 했나

#### 2-1. 기본값으로 메우지 않는다

발볼 "보통" · 와이드 false · 카본 초안 값을 기본값으로 넣었더니 **결손률이 가려졌다**(얼마나 모르는지가 안 보인다). 그래서 V4 에서 발볼 · 와이드 · 카본을 NULL 허용으로 바꾸고, 화면은 NULL 을 "정보 없음"으로 보인다. 모르는 것을 모른다고 보이는 것이 "스펙은 빠짐없이"보다 먼저다.

#### 2-2. 약관은 "사실 값"과 "지재권 정보"를 나눠 읽는다(2026-10-24 사용자)

한국 쇼핑몰 약관 대부분(공정위 표준약관)에 "회사에 지식재산권이 귀속된 정보를 영리 목적으로 이용하지 마라"가 있다. 대상은 글 · 사진 · 디자인이다 — **무게 · 드롭 · 가격 같은 사실 값은 지재권 대상이 아니다.** 그래서 사실 값만 쓰고 글 · 사진은 옮기지 않는다. 다만 세 경우는 쓰지 않는다:
- 사실 값까지 스스로 권리 대상으로 선언한 곳(다나와 판매점 약관 제17조 ① "상품정보 및 가격정보를 포함한 모든 게시물")
- 자동 수집을 직접 금지한 곳(나이키 5조 "데이터 마이닝, 로봇, 스크래핑" · 알트라 글로벌 · 리닝 · 엑스텝 · Running Warehouse)
- robots 가 필요한 경로를 막은 곳(무신사 · SSG · GS샵은 `User-agent: *` 에 `Disallow: /` — 검색 결과로만 본다)

약관을 못 읽은 곳(봇 방어가 막은 아디다스 · 호카 · 온 · 언더아머)은 허용으로 보지 않는다 — **정직한 UA 로 못 받는 곳을 위장해서 받지 않는다.** 이 기준은 법률 자문이 아니라 이 프로젝트의 수집 기준이다.

#### 2-3. 가격은 정가만

할인가는 그날 그 가게의 값이라 내일 바뀌고 다른 곳에선 또 다르다. 비교 사이트의 가격이 "그 신발의 값"이 되려면 어디서 봐도 같은 값이어야 한다. 그래서 정가(발매가)만 쓰고, 어디서 언제 읽었는지를 같이 둔다.

#### 2-4. 실측값은 공시값과 섞지 않는다

리뷰 매체가 직접 잰 값(RunRepeat 실험실 · RTINGS · Running Warehouse 자체 측정 · Doctors of Running · solereview)은 사이즈 · 측정법이 매체마다 달라 공시값과 비교할 수 없다. 공시값 칸에는 제조사 값만 넣고, 실측은 사람이 따로 적은 것만 `measured_*` 에 둔다. 어느 쪽을 화면에 쓸지는 비교 페이지에서 정한다.

#### 2-5. 현행은 "국내 판매" 기준

이 사이트의 사용자는 국내에서 신발을 사는 사람이다. 글로벌 신형이 국내에 없으면 그 사람이 살 수 있는 가장 새 세대가 현행이다.

#### 2-6. 판단을 사람과 Claude 로 나눠 남긴다

웹 검색 판단은 `via: web, by: claude`, 사람 판단은 `by: user` 로 남긴다. 나중에 "이 값을 누가 왜 넣었나"를 물을 수 있어야 하고, Claude 판단만 골라 다시 볼 수 있어야 한다(지금 판단 칸 618개 중 Claude 웹 검색 458 · 관리 화면 43 · 사람 승인 27 · 직접 확인 22).

- **수집처 후보를 하나씩 뺐다(2026-10-21 ~ 10-29).**
  - 다나와: robots 가 목록 넘기기를 막고, 판매점 약관이 가격정보를 저작물로 선언 → 뺐다. 시드 20켤레는 사용자가 다나와를 보며 **손으로** 채운 값이었다.
  - 네이버 쇼핑 검색 API: 2026-07-31 종료. 쿠팡 파트너스 API: 최종 승인이 있어야 하고 판매가로 보여 뺐다.
  - 크림: 이미지로 봤을 때는 CDN 이 외부 Referer 에 403 · 약관이 이미지 권리를 회사에 둠. 발매가로 다시 봤을 때(10-29)는 약관에 자동 수집 금지는 없었지만 **서버가 비브라우저 접속에 HTTP 500(빈 본문)** — Playwright 도 500 이라 차단 신호로 보고 멈췄다. 브라우저로 위장하지 않았다. 지금 크림 가격 26칸은 관리 화면에서 사람이 넣은 값이다.
  - Running Warehouse: 약관이 수동 추출까지 금지. RunRepeat: 유료 상업 라이선스.
- **"참고가로 통일"을 하루 만에 취소했다(2026-10-28).** 웹 검색 100행 시험에서 다나와 공식판매처 23% · 쿠팡 0% 만 나왔고, 값이 최저가(할인가)라 정가 기준과 맞지 않았다.
- **ABC마트는 처음에 쓰지 않았다가(10-24) Playwright 로 쓰게 됐다(10-28).** 목록이 JS 렌더링이라 주소를 얻을 길이 없었다. 렌더링은 차단을 넘는 것이 아니라 공개 페이지를 읽는 방식이라 같은 조건(우리 UA · 5초 · 차단이면 중단)으로 승인받았다. 정가 빈 칸 13행을 채웠다. ABC마트의 "사이즈 추천 통계"는 시험 11행이 전부 "보통"이라 발볼 근거로 쓰지 않았다.
- **기존 DB 값 상당수가 Running Warehouse 실측이었다(10-23).** 보스턴 13 스택 37 · 베이퍼플라이 4 무게 167 등이 Running Warehouse 가 직접 잰 값과 같았다. "DB 값이 Running Warehouse 값과 같으면 실측으로 본다"를 규칙으로 두고, 공식값이 확인된 칸만 남겼다.

- **와이드 true 17건이 오염됐었다(10-23).** "2E" · "와이드" 낱말만으로 잡았더니 몰 메뉴("옴니9 와이드"가 사우코니 12행에), 리뷰어 자기 신발("my 10.5 2E"), 부정문("doesn't come in a wide version" — 정반대 뜻), 독자 댓글이 들어왔다. 그 모델 · 세대 리뷰 본문만, 댓글 앞까지 읽게 바꿨다.
- **국내몰에 없다는 이유로 넣었던 와이드 false 23행을 비웠다(10-24 사용자 정정).** 웨이브 라이더 29 는 국내몰에 와이드가 없었지만 미즈노 미국 공식몰에 2E 가 있었다. 국내 라인업은 글로벌의 일부라 "국내몰에 없음"은 "없음"의 근거가 아니었다.
- **와이드를 둘에서 넷으로 나눴다(11-02 사용자).** "침묵으로 없음을 증명하지 않는다" 규칙 때문에 185켤레가 비어 있었다. 사용자 판단: 다섯 단계를 다 찾아도 안 나오면 실제로 없을 가능성이 높다 → "없음"으로 본다. 대신 10-24 의 문제(국내에 없을 뿐인 것)는 **"국외에만 있음"이라는 값으로 따로 담는다.** 이 결정 직전의 조사에서 웨이브 라이더 29 는 국내몰에 "WAVE RIDER 29 SW"(슈퍼 와이드)가 새로 올라와 있었다 — 국내 사정은 바뀐다.
- **국내몰 "사이즈 옵션"으로 와이드를 가리려다 그만뒀다(11-02).** 아식스 국내몰의 사이즈 칸은 mm 만 있고, 와이드는 별도 품번 상품으로 판다. "표준만 있으면 없음"으로 읽으면 아식스 전부가 틀린 "없음"이 된다. 여섯 브랜드 71켤레를 Playwright 로 다시 본 결과 새로 찾은 와이드는 0건이었다 — 뉴발란스 국내몰은 "퓨어셀" · "SC" 처럼 표기가 다르고 검색이 여러 낱말 · 품번을 못 찾았다.
- **StockX 품번으로 와이드를 찾으려다(11-02)** 캐시 전체에 남성 와이드 상품이 14개뿐이라는 것을 알았다(되팔이 시장이라 와이드가 드물다). 새로 알게 된 것은 아디제로 SL 1 하나였다.
- **발볼 — RSG 정형 칸을 쓰지 않기로 했다(11-02).** RSG 페이지의 "Our tester's take … Toebox Normal/Wide/Tight" 칸으로 78켤레를 채울 수 있었지만, 이미 발볼이 있는 49켤레와 **41% 만 일치**했고 값의 75% 가 Normal 이었다(기본값처럼 쓰인 칸). 10-24 에 뺀 "표 라벨"과 같은 것이다. 대신 리뷰 본문 문장 37켤레를 사람이 읽고 승인한 19켤레만 넣었다 — 자동 판정은 "loose toebox"를 "tight" 낱말 때문에 좁음으로, "roomy 를 원하면 실망"을 넓음으로 읽는 등 틀린 것이 많았다.
- **입문 라인을 되살렸다(10-24 사용자).** "허용 매체에 리뷰가 없다"는 이유로 입문 17라인을 뺐었는데, 국내에서 많이 팔리는 모델이 통째로 빠지면 안 된다는 판단으로 되살렸다(33행). 스펙은 웹 검색으로 채웠다.
- **트레일을 78라인에서 50으로 줄였다(10-21).** 세대 추정이 약한 것 · 하이킹 겸용 · S/LAB 판 · 브랜드 안에서 겹치는 성격 순으로 뺐다.
- **울트라부스트 4 후보를 뺐다(11-03 사용자).** 직전 세대 자리의 FY9120 은 2017~18년 `Ultra Boost 4.0 DNA` 로, 2024년 울트라부스트 5 의 직전이 아니었다. 직전은 울트라부스트 라이트(2023)지만 세대 번호가 없어 `(line_key, generation)` 한 행으로 이을 수 없고, 이미지 매칭(`stockx.mjs judge`)도 제목의 세대 숫자로 고른다 — 번호를 지어 붙이지 않고 행을 뺐다(운영에 없던 `review` 행).
- **현행 세대를 다시 확인했다(11-01).** 운영 현행 중 확신도가 낮은 65켤레를 BITR · RSG 사이트맵으로 대조했다. "리뷰 없음"은 "신형 없음"이 아니라는 원칙(사용자)으로, 확인 못 한 14켤레는 그대로 뒀다. 린콘 5(국내 미출시)를 넣지 않은 일로 "현행 = 국내 판매 중인 최신 세대" 규칙이 생겼다.
