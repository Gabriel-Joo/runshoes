#### 0. 한 줄 요약

신발을 등록 · 수정 · 숨김 · 영구 삭제하는 관리 화면이다. 칸마다 **출처를 같이 저장**하고, 근거 없는 값이 생기지 않게 막는다 — 값을 바꾸면 출처를 다시 고르게 하고, 와이드 "없음"은 출처가 있어야 저장된다. 여기서 고친 값은 다음 적재에서 되돌려지지 않는다(`01c_catalog_loader.md`).

#### 1. 최종 설계

#### 1-1. 목록 — 세 탭

| 탭 | 무엇 | 누가 |
|---|---|---|
| 등록된 신발 | 전체 목록. 정렬 `최근 수정순`(기본) · `등록순` · `브랜드순` · `모델명순` — 고른 것을 다시 누르면 방향이 바뀐다 | admin · 데모 관리자 |
| 숨긴 신발 N | 숨긴 신발과 숨긴 시각. 되살리기 · 영구 삭제 | 보기는 둘 다, 쓰기는 admin |
| 보완 필요 N | 빈 칸이 있는 신발. 칸 하나로 거를 수 있고, 기본은 **빈 칸 적은 순**(한 칸만 빈 신발부터 고치면 목록이 빨리 준다) | admin · 데모 관리자 |

- **보완 필요의 "빈 칸"** — 가격 · 발볼 · 와이드 · 스택 · 미드솔 · 카본 · 중량 · 드롭 · 중량 사이즈(중량은 있는데 사이즈가 빈 것) · 품번. 와이드 · 카본은 `null` 만 센다 — `false`(없음)는 확인한 값이다. 지금 운영: 발볼 196 · 와이드 184 · 가격 170 · 중량 사이즈 69 · 카본 43 · 스택 42 · 미드솔 17 · 중량 2 · 드롭 1 · 품번 1.
- **수정 이력 칸** — 마지막 수정의 바뀐 칸 이름(`lastChange`) 두 개까지, 넘으면 "외 N건", 마우스를 올리면 전체. 날짜는 `updatedAt`(MM-DD HH:mm). 등록 · 숨김 · 되살리기도 찍힌다. 대표 · 추가 이미지는 "이미지", 가격 출처 · 날짜 · 종류는 "가격 출처" 하나로 묶는다.
- 최근 수정순에서 고친 적 없는 신발은 방향과 상관없이 뒤에, id 순. 그래서 정렬은 **화면에서** 한다 — 서버 `_sort` 로는 "null 은 늘 뒤"를 나타낼 수 없다.
- 탭 · 거르기 · 정렬 · 브랜드 · 검색은 주소(`?tab=gaps&gap=width …`)에 둔다 — 수정 화면에서 저장 · 취소하면 보던 자리로 돌아온다.

#### 1-2. 등록 · 수정 폼

```
기본    브랜드 · 모델명 · 용도 · 안정성
세대    라인키 · 세대 · 현행 · 성별, 품번
스펙    중량 [g] [기준 사이즈]  출처      드롭 [mm]  출처      스택하이트 [mm]  출처
        미드솔  출처      발볼  출처      와이드 모델  출처      카본 플레이트(출처 면제)
가격    가격(발매가) · 확인한 날 · 출처
이미지  주소 목록 — 첫 번째가 대표, 6개까지
문구    한 줄 요약 · 상세 설명
```

| 칸 | 선택지 | 저장 값 |
|---|---|---|
| 스펙 출처 | BITR · RSG · STORE · PR · WEB(웹 문서 · Claude 검색) · MAN(직접 확인 · 관리자) | 코드. WEB · MAN 은 주소 칸이 나오고 **둘 다 주소 필수** |
| (기존 값에만) | DB · SX | 고를 수 없다 — 회색으로 보이고, 값을 고치면 새 출처를 골라야 저장된다 |
| 와이드 출처에만 | NOTFOUND(검색 결과 없음) | 다섯 단계를 다 찾아도 안 나온 "없음"의 근거 |
| 와이드 모델 | 있음(국내) · 국외에만 있음 · 없음 · 정보 없음 | `true`+`domestic` · `true`+`overseas` · `false` · `null`. 예전 값 "있음(국내 · 국외 미확인)"은 `true`+`null` 로 보인다 |
| 발볼 · 카본 | 값 · 정보 없음 | 정보 없음 = `null` |
| 중량 기준 사이즈 | US M9 · M9.5 · M10 · M10.5 · M8.5 · 불명 | 불명 = `null` |
| 가격 출처 | 공식몰 · ABC마트 · 크림 · MAN(직접 확인) | 종류는 늘 `발매가`. 기존 `다나와` 는 회색으로만 |
| 성별 | 남성 · 여성 · 공용 | `men` · `women` · `unisex` |

**근거 없는 값을 막는 규칙**
- 값을 바꾸면 **그 칸의 출처를 다시 고르게** 한다 — 옛 출처가 새 값에 붙지 않게. 가격을 바꾸면 확인한 날 · 출처도 다시.
- 값을 비우면 출처도 비운다.
- **와이드 "없음"은 출처가 있어야 저장된다** — 없으면 "없음은 출처가 필요해요(못 찾았으면 "검색 결과 없음")". 이 검사는 폼만 한다(서버가 막으면 옛 계약이 깨진다 — `05_api_contract.md` 1-5).
- 새로 고른 MAN 은 주소가 필수다. 예전에 주소 없이 넣은 MAN 은 그대로 저장할 수 있다.

**입력**
- 중량 · 드롭 · 스택은 숫자와 소수점 한 자리, 가격은 정수 7자리. `type="number"` 는 쓰지 않는다 — `e` · `+` · `−` 가 들어가고 휠로 값이 바뀐다. 붙여 넣기도 같은 검사. 서버도 숫자가 아니면 400.
- 품번은 영문 · 숫자 · `-` `.` `/` · 공백 50자. 힌트 "예: 1011C284 (색상 코드는 빼고 모델 번호만)".
- 이미지 — 칸 하나에 주소 하나, `+` 로 칸 추가 · `−` 로 빼기, 왼쪽 핸들(≡)을 끌어 순서를 바꾸고 1번 자리가 대표. 마우스 · 터치 · 펜(Pointer Events), 키보드는 핸들에서 ↑ · ↓. 썸네일은 주소를 멈추고 0.5초 뒤 다시 불러오고, 못 불러오면 빨간 테두리. 저장은 `images` = 빈 칸을 뺀 목록, `image` = 그 첫 번째.
- 수정 화면은 **신발을 받기 전에는 폼을 그리지 않는다** — 빈 폼에 먼저 입력한 값을 늦게 온 응답이 덮지 않게.

#### 1-3. 숨김 · 되살리기 · 영구 삭제

- **삭제 버튼은 "숨김"이다**(V8). 확인 창에 그 신발의 리뷰 수 · 찜 수, 현행 세대를 숨겨 그 라인에 현행이 없어지면 "이 라인에 현행이 없어집니다" 경고 — 다른 세대를 저절로 올리지 않는다. "숨긴 신발 탭에서 언제든 되살릴 수 있어요".
- 숨긴 신발은 목록 · 상세 · 찜 · 리뷰 쓰기에서 빠지고, 리뷰 · 찜은 DB 에 남는다. 되살리면 그대로 돌아온다.
- **영구 삭제는 숨긴 신발만**(보이는 신발 409 `not_hidden`), admin 만. 리뷰 · 답글 · 도움이 돼요 · 찜이 함께 지워진다. 지우기 전에 `shoe_purges` 에 남기고, 적재기가 그 기록을 읽어 다시 넣지 않는다.
- 같은 라인 · 세대 · 성별의 숨긴 신발이 있으면 새로 등록하지 못한다(409 `hidden_generation` — "되살려 주세요").

#### 1-4. 누가 무엇을

| | admin | 데모 관리자(`DEMO_ADMIN`) | 그 밖 |
|---|---|---|---|
| 목록 · 폼 · 숨긴 신발 보기 | 된다 | 된다 | 메뉴 없음 |
| 저장 · 숨김 · 되살리기 · 영구 삭제 | 된다 | **서버가 403** — 화면은 그 문구("데모 관리자 계정은 할 수 없습니다")를 그대로 띄운다 | 401 · 403 |

- 화면만 막지 않는다 — API 로 우회할 수 있으므로 서버(`api/Viewer`)가 막는다. 데모 관리자로 들어가는 길은 `04_auth.md`.

#### 1-5. 기록

- 관리자 등록 · 수정 · 숨김 · 되살리기는 행에 `updated_at` · `last_change` 를 찍고, 활동 로그에 `shoe.create` · `shoe.update`(바뀐 칸 이름만) · `shoe.delete` · `shoe.restore` · `shoe.purge` 를 남긴다.
- 바뀐 칸은 저장 전후의 응답 문서를 칸마다 비교해 정한다. 바뀐 것이 없는 저장은 찍지 않는다.
- 적재기의 쓰기(`X-Runshoes-Client: loader`)는 찍지 않는다 — "최근 수정순"에 사람의 수정만 보이게.

#### 2. 왜 이렇게 했나

- **출처를 칸마다 저장한다(2026-10-29 사용자).** 이 아카이브의 값은 사이트마다 다르다(공시 무게 · 실측 무게 · 국내 정가). 어디서 읽었는지 없이는 값을 믿을 수도, 다시 확인할 수도 없다.
- **"정보 없음"을 고를 수 있어야 한다.** 예전 폼은 카본 · 와이드가 체크박스라 한 번 누르면 `true/false` 만 남았다 — 확인하지 않은 `false` 가 생겼다. 발볼 선택에는 "정보 없음"이 없어 `null` 인 210행에 첫 선택지 "좁음"이 보였다. 이제 모든 사실 칸에 `null` 을 고를 수 있다.
- **"없음"은 근거가 있을 때만(2026-10-24 원칙).** 찾지 못한 것은 없는 것이 아니다. 근거 없는 와이드 `false` 23행을 비운 적이 있어 저장 단계에서 막는다.
- **WEB 과 MAN 을 가르는 것은 누가 확인했나다(2026-11-02 사용자).** 둘 다 주소를 남긴다 — WEB 은 Claude 가 검색해 찾은 값, MAN 은 사람이 직접 보고 넣은 값.
- **지우지 않고 숨긴다(2026-10-30 사용자).** 지우면 리뷰 · 찜이 사라진다. 실수로 숨겨도 되살릴 수 있게 하고, 정말 지울 때만 영구 삭제를 따로 둔다.
- **데모 관리자는 읽기 전용(2026-10-29 사용자).** 처음 보는 사람이 관리 화면을 그대로 둘러볼 수 있어야 하지만, 공개 체험 계정이 데이터를 바꾸면 안 된다.

#### 3. 시도했던 것들

- **관리 화면에서 고친 값을 적재기가 되돌렸다(2026-10-29 발견).** 적재기는 카탈로그가 정답이라 DB 와 다르면 PATCH 했다. 적재 전에 운영의 사람 수정을 `decisions.json` 으로 가져오게 했다 — 사용자가 "가장 중요 — 구현 순서 맨 앞"으로 정했다. 자세한 것은 `01c_catalog_loader.md`.
- **품번 형식을 넓혔다(2026-11-01).** 처음 규칙 `[A-Za-z0-9-]` 은 리허설에서 실제 카탈로그 값 5켤레(온 `71.98674`, 미즈노 `411448-RBUN / U1GD241751` 등)를 막았다. `.` `/` 공백을 더했다. 힌트도 처음에는 "색상 포함"이었다가 모델 번호만으로 바뀌었다(가격은 색상과 무관하고, 색상별 이미지를 여러 장 쓴다).
- **이미지 칸이 셋을 거쳤다(2026-10-30 → 11-01).** 대표 · 추가를 따로 두던 것 → 목록 하나에 "대표로 지정" 버튼 → 핸들로 끌어 놓기. 1번 자리가 대표라는 규칙 하나로 줄었다.
- **늦게 온 응답이 입력을 덮었다(2026-11-01, V11 리허설).** 수정 화면이 신발을 받기 전에 빈 폼을 그려, 발볼을 고른 뒤 응답이 와 "보통"으로 되돌아갔다. 받기 전에는 폼을 그리지 않게 고쳤다.
- **적재기 스냅숏을 한 건씩 쓰게 했다(2026-11-01).** 리허설에서 품번 220건을 쓰고 멈춘 뒤 다시 돌리자, 그 220건이 관리자 수정으로 잘못 가져와졌다. 쓰기 한 건마다 스냅숏을 고친다.
- **"삭제"를 "숨김"으로 부른다(2026-11-01).** 버튼이 "삭제"인데 실제로는 숨겼다 — 영구 삭제가 생기며 이름을 나눴다.

#### 4. 남은 한계

- **보완 필요가 많다.** 302켤레 중 261켤레에 빈 칸이 있다. 대부분 발볼 · 와이드 · 가격이다 — 와이드는 재조사가 채운다(`01a_catalog_sources.md` 1-7).
- **수정 이력은 마지막 한 번만 행에 있다.** 그 전 이력은 활동 로그(`shoe.update`, 180일)에만 있고, 바뀐 칸 이름만 남는다 — 이전 값은 어디에도 없다.
- **서버는 와이드 "없음"의 출처를 보지 않는다.** API 로 직접 쓰면 출처 없는 `false` 가 들어갈 수 있다.
- **목록은 늘 전부 받는다.** 302켤레 전체를 받아 화면에서 거르고 정렬한다.
- **동시 수정을 막지 않는다.** 두 관리자가 같은 신발을 고치면 나중 저장이 이긴다(관리자는 사실상 한 명).

#### 5. 검증 항목

- 계약 시험 spring-v6 — 데모 관리자 403(X10~X16) · 숨김 · 되살리기(X30~X43) · 품번 · 수정 이력 · 적재기 제외 · 영구 삭제(X100~X115) · 와이드 범위 · NOTFOUND(X116~X122).
- 적재기 건조 실행이 관리 화면 수정 뒤에도 그 칸을 되돌리지 않는지(`어드민 수정 N건` 가져오기 로그).
- 화면: 값을 바꾸면 출처가 비는지 · 와이드 "없음"에 출처 없으면 저장되지 않는지 · 데모 관리자로 저장하면 문구가 뜨는지.
