#### 0. 한 줄 요약

React 단일 페이지 앱이다. 홈 하나에서 **찾고(용도 · 검색 · 정렬) → 카드를 누르고 → 상세 모달에서 스펙 · 리뷰를 본다.** 그 옆에 추천받기(5문항 → 점수순), 비교하기(고른 신발을 점수 없이 나란히), 러너들의 선택(랭킹)이 있다. 값이 없으면 칸을 숨기지 않고 "정보 없음"으로 보여 준다.

#### 1. 최종 설계

#### 1-1. 라우트

| 라우트 | 화면 | 누가 |
|---|---|---|
| `/` | 홈 — 히어로 슬라이드 · 용도 칩 · 검색 · 정렬 · 찜만 보기 · 카드 그리드 · 상세 모달(`?shoe={id}`) | 누구나 |
| `/recommend` | 추천받기 — 5문항 → 점수순 결과 | 누구나 |
| `/compare` | 비교하기 — 2~5켤레를 나란히(`?ids=` · `?pick=`, `08_compare.md`) | 누구나 |
| `/best` | 러너들의 선택 — 종합 점수 1~5위 · 용도별 1위 | 누구나 |
| `/login` · `/signup` | 로그인 · 가입. 성공하면 `returnTo`(같은 사이트 경로만)로 | 누구나 |
| `/account` | 마이페이지(`?tab=`) | 로그인 |
| `/admin` · `/new` · `/edit/:id` | 관리 화면(`03_admin.md`) | admin · 데모 관리자 |
| `*` | NotFound | |

- 경로 가드(`RequireAuth`)는 화면 안내용이다 — 권한은 서버가 막는다.
- 화면을 옮기면 맨 위에서 시작한다(`ResetScroll`). 경로가 실제로 바뀔 때만 — 상세 모달(`?shoe=`) · 마이페이지 목차(`?tab=`)는 스크롤을 그대로 두고, 뒤로 · 앞으로는 브라우저에 맡긴다.

#### 1-2. 홈

- **용도 칩** — 전체 · 조깅·회복주 · 템포·인터벌 · LSD·장거리 · 레이스 · 트레일.
- **검색** — 브랜드 · 모델 · 영어 이름 · 검색용 다른 표기(V13)를 서버가 거른다(`?search=`, 낱말 AND · 대소문자 · 공백 무시 — `젤카야노` · `SC 페이서` · `퓨어셀` 도 맞는다).
- **정렬** — 기본 · 평점순 · 리뷰순 · 좋아요순(서버 `_sort`). **찜만 보기**는 별도 페이지가 아니라 토글이다(로그인했을 때만).
- 거르기 · 정렬은 모두 서버가 하고, 화면은 받은 목록을 그린다. 카드: 사진 · 브랜드 · 모델 · 용도 · 요약 · 중량 · 드롭 · 발볼 · 안정성 · 카본 · 평점 · 리뷰 수 · 찜.
- **카드 높이는 같은 줄끼리 맞춘다**(2026-11-09 사용자). 요약은 줄 수를 자르지 않고, 화면에서 같은 줄에 뜬 카드끼리 모델명 · 요약 칸을 그 줄의 가장 긴 높이에 맞춘다(셋이면 셋 중, 둘이면 둘끼리, 혼자면 제 길이) — 아래 스펙 · 평점 줄이 그 줄 안에서 같은 높이에 온다. `CardRowSync`(`App.tsx` 에 하나)가 카드의 화면 위치(top)로 줄을 가르고 `min-height` 를 넣는다. 폭이 바뀌거나 목록이 바뀌거나 글꼴이 늦게 오면 다시 잰다. 요약 문구 규칙은 `01d_catalog_copy.md`.
- 찜을 누르면 계정별로 저장된다(`PUT/DELETE /api/shoes/{id}/like`). 비로그인은 로그인 화면으로 갔다가 돌아온다.

#### 1-3. 상세 모달

- 주소 `?shoe={id}` — 새로 고침하거나 로그인하고 돌아와도 같은 신발이 열린다. 배경을 누르면 닫힌다.
- **사진** — 2장 이상이면 좌우 화살표 · 썸네일 줄(끌어서 넘긴다), 1장이면 사진만. 이미지가 없거나 못 불러오면 자리표시로 레이아웃을 지킨다. PC 는 화살표 · 신발 가운데가 오른쪽 스펙표의 스택하이트 아래 구분선에 온다(요약 문구가 있는 신발 기준 — 없는 8켤레는 구분선이 34px 위, 2026-11-03 사용자: 그대로 둔다).
- **영어 이름** — 브랜드 줄에 가운뎃점으로 붙인다(`뉴발란스 · FuelCell SuperComp Pacer v2`, 브랜드와 같은 크기 · 색). 없으면 브랜드만. 홈 카드에는 넣지 않는다(카드가 복잡해 보인다, 2026-11-03 사용자). 검색용 다른 표기는 보이지 않는다.
- **스펙** — 중량 · 드롭 · 스택하이트 · 발볼 · 와이드 모델 · 안정성 · 미드솔 · 카본 플레이트 · 가격. 용어마다 툴팁(`terms`, 한 번에 하나만 열린다, 화면 밖으로 나가지 않는다).
  - 값이 없으면 **"정보 없음"** — 칸을 숨기지도, 기본값으로 메우지도 않는다.
  - 와이드 모델: 있음 · 국외에만 있음 · 없음 · 정보 없음(`wideLabel`). "없음"에는 출처를 붙이지 않는다(검색 결과 없음은 작업 과정, 2026-11-02 사용자).
  - 와이드 모델 ⓘ 는 값 넷을 다 설명한다(2026-11-03 사용자 문구) — `terms` 테이블은 읽기 전용이라 이 툴팁만 화면이 가진다(`src/utils/terms.ts WIDE_TERM` — 상세 모달 · 비교표가 같이 쓴다).
  - 가격은 **"발매가 199,000원"** — 평점 줄과 같은 꼴(글자 14px · 숫자 22px). 출처 · 읽은 날은 모달에 내지 않는다 — "크림 2026/11/01 기준"이 그 곳에서 지금 그 값에 파는 것처럼 보였다(2026-11-03 사용자). 관리 화면에만 있다.
  - 한 줄 요약은 강조색 굵게(크기 그대로).
- **리뷰 요약** — 리뷰 3개 이상이면 AI 요약(좋았던 점 · 아쉬운 점, "의견이 갈립니다"). 요약이 없으면(`summary: null`) 카드를 숨긴다.
- **리뷰** — 처음에는 하나만: "도움이 돼요"가 가장 많은 리뷰(동점이면 최신, 전부 0 이면 최신 — 베스트 표시 없이). 나머지는 "리뷰 전체보기"로 편다.
  - 쓰기 폼은 셋 중 하나: 로그인 안내 · "이미 썼어요" · 작성 폼(별점 · 내용 10~300자, 남은 글자 수). 작성자는 계정 닉네임이라 입력 칸이 없다.
  - 내 리뷰는 그 자리에서 고친다(인라인). 지우기는 내 리뷰 또는 admin, 확인 창을 거친다. "도움이 돼요"는 남의 리뷰에만 — 누르면 숫자만 바뀌고 순서는 그대로(베스트가 튀지 않게).
  - **쓰는 중에 로그인이 끝나도** 쓰던 내용을 탭 안(sessionStorage)에 남겨, 다시 로그인하면 같은 신발 모달에서 이어 쓴다.
- 로그인한 사람이 모달을 열면 조회 기록(`shoe.view`)을 남긴다(같은 신발 30분에 한 번은 서버가 거른다).
- **비교에 담기** — 평점 · 가격 줄 아래 오른쪽 버튼. 마지막 비교 구성(이 브라우저)이 있으면 한 칸 더하고, 없으면 그 신발로 비교하기를 연다(4켤레까지 채운다). 비교하기 안에서 연 모달에는 없다.

#### 1-4. 추천받기 `/recommend`

- 다섯 문항(용도 · 발볼 · 안정성 · 쿠션 · 예산)에 답하면 상위 3켤레. **계산은 서버**(`GET /api/recommend`), **배점 · 경계 · 문구 · 데이터가 없을 때의 처리는 `10_recommend.md`**.
- 1위는 이유를 모두, 2~3위는 맞은 이유(✓)만 셋까지 보인다. 데이터가 없어 못 본 조건(ⓘ 회색 줄)은 순위와 상관없이 목록 맨 위에 보인다.
- 기다리는 동안 "고르는 중이에요…", 실패하면 "추천을 불러오지 못했어요".
- 결과 아래 **"1~3위 비교하기"** — 결과 그대로 비교하기로(이미 고른 신발이라 자동 채우기는 하지 않는다).

#### 1-5. 러너들의 선택 `/best`

```
score = rating × 20 × (reviewCount / (reviewCount + 3)) + likeCount × 0.5
```

- 평점만으로 순위를 매기면 "리뷰 1개에 5점"이 1위가 된다. 리뷰가 적을수록 평점 반영률을 낮춘다 — 리뷰 1개면 25%, 3개면 50%, 10개면 약 77%. 좋아요는 보조로 조금 더한다. 산식을 화면에도 적는다.
- 종합 1~5위와 용도별 1위.

#### 1-6. 마이페이지 `/account`

- 왼쪽 목차 · 오른쪽 본문. 본문 맨 위에는 늘 활동 요약(리뷰 · 찜 · 도움이 돼요 · 가입일). 휴대폰은 목차 아래 가로선.
- 목차: 회원정보 수정(이메일은 보기만, 닉네임 · 비밀번호 따로 저장) · 내 활동(내 리뷰 · 찜 목록 · 도움받은 리뷰) · 회원 탈퇴.
- **내 리뷰 · 도움받은 리뷰** — 표. 내용을 누르면 전문 모달(읽기 전용). 왼쪽 체크박스로 여러 개 골라 한꺼번에 삭제 · 도움 취소.
- **찜 목록** — 홈 카드와 같은 칸을 같은 순서로(나란히 놓고 비교하게, 가격은 뺐다). 행택 모양 카드 — 위에 끈 구멍, 아래 바코드(Code 39, `RS` + id 네 자리). 여러 개 골라 한꺼번에 해제하거나, 2~5개를 골라 **"선택 비교"**로 비교하기를 연다. 사진은 홈 카드처럼 좌우 11% 를 띄운다(StockX · GOAT 사진 비율이 달라 높이만 정하면 GOAT 신발이 크게 보인다).
- 한꺼번에 하는 일은 새 API 없이 기존 DELETE 를 하나씩 차례로 부른다. 일부가 실패하면 "N개 중 M개 …"로 알리고 실패한 것은 고른 채 둔다.
- 회원 탈퇴 — 확인 화면. "계속 이용하고 싶어요"가 강조 버튼, "회원 탈퇴"는 빨간 테두리.

#### 1-7. 공통

- **헤더** — 로고 · 홈 · 추천받기 · 비교하기 · 러너들의 선택 · 등록·관리(admin · 데모 관리자) · 로그인/계정 메뉴. 메뉴는 넷 다 같은 색이고 지금 보는 화면만 강조색(2026-11-09). 768~899px 는 로고 32px · 메뉴 17px · 간격 12px — 관리자 · 닉네임까지 붙으면 폭을 넘어 페이지가 옆으로 밀렸다. 휴대폰은 햄버거 서랍. 계정 메뉴는 연 그 이동에서만 열려 있다.
- **챗봇** — 왼쪽 아래(오른쪽 아래 "맨 위로" 단추와 대칭). 같은 Pod 의 파이썬 사이드카(`chatbot/`)와 WebSocket(`/ws/chat`)으로. 신발을 말한 답 아래에는 "보러 가기" 버튼 하나 — 1켤레는 상세 모달, 2켤레 이상은 비교하기(작업 5-1, `09_chatbot_rag.md` 15절). 창을 닫으면 대화가 지워진다. 로그인한 사람만 쓴다 — 버튼은 누구에게나 보이고, 로그인 전에 누르면 패널 안에 "챗봇은 로그인한 뒤에 쓸 수 있어요. 체험 계정으로 바로 둘러볼 수 있어요." 와 [로그인](보던 화면으로 돌아온다). 로그아웃하면 연결을 닫는다(`09_chatbot_rag.md` 17절).
- **반응형** — 1200px 이상 데스크톱 · 768~1199px 태블릿 · 767px 이하 휴대폰. 카드 그리드 3열 → 2열 → 1열, 목록 → 상세 모달 흐름은 모든 크기에서 같다. 검색창은 1200px 이상 칩 오른쪽, 그 아래로는 칩 위 한 줄.
- 확인 창은 공통 `ConfirmModal`(신발 숨김 · 리뷰 삭제 · 한꺼번에).

#### 2. 왜 이렇게 했나

- **홈 하나에 목록 · 상세를 둔다.** 과제 요건이 "단일 화면 구조 유지"였다. 상세를 모달로 두고 주소(`?shoe=`)에 남겨 링크 · 새로 고침 · 로그인 왕복에도 같은 화면으로 돌아온다.
- **"정보 없음"을 보여 준다.** 빈 칸을 숨기면 "없다"로 읽히고, 기본값(`보통` · `없음`)으로 메우면 거짓이 된다. 이 아카이브는 출처가 있는 값만 싣는다(`01a_catalog_sources.md`).
- **종합 점수에 신뢰도 가중치.** 리뷰 수를 더하면 리뷰가 많은 신발이 무조건 이기고, 평점만 보면 리뷰 1개가 이긴다. 리뷰 수로 평점 반영률을 조절했다.
- **리뷰는 하나만 먼저.** 모달이 길어지지 않게 가장 도움이 된 리뷰 하나를 보이고 나머지는 펼친다.
- **찜 카드를 홈 카드와 같은 칸 · 같은 순서로(2026-10-30 사용자).** 찜 목록은 고른 신발을 나란히 비교하는 곳이다.

#### 3. 시도했던 것들

- **json-server 시절의 공용 찜 · 클라이언트 평점(→ 2026-10-21).** 찜은 모두가 같이 쓰는 칸이었고, 평점 · 리뷰 수는 화면이 계산해 PATCH 했다. 로그인과 함께 찜은 계정별, 숫자는 서버가 세게 바뀌었고, 화면은 쓰기 뒤 목록만 다시 받는다.
- **상세 갤러리를 지웠다가 되살렸다(2026-10-30).** 카탈로그를 넓힐 때(`d3ff385`) 사진이 한 장뿐이라 갤러리를 지웠다. 색상 이미지를 모으면서 지금 사진 칸에 맞춰 되살렸다(`01b_catalog_images.md`).
- **화살표를 글자에서 SVG 로(2026-10-30).** 글자 ‹ › 는 글꼴 기준선 때문에 가운데가 맞지 않았다 — `Chevron` SVG 로 바꿔 어긋남 0px.
- **스크롤 되돌리기가 상세 모달에서 튀었다(2026-10-30).** 처음에는 이동 방식만 바뀌어도 맨 위로 올려 모달을 열 때 튀었다. 이전 경로와 비교해 실제로 바뀔 때만 올린다.
- **마이페이지를 여러 번 다듬었다(2026-10-30 사용자, 1~5차).** 목차 · 활동 요약 글자 크기를 홈 정렬과 같은 토큰으로, 한꺼번에 버튼 이름("선택 삭제"가 체크박스 해제처럼 읽혀 "리뷰 삭제 · 찜 해제 · 도움 취소"로), 찜 카드 행택 · 바코드, "공감" 대신 "도움이 돼요".
- **화면 검증에서 찾은 것(2026-10-21).** `/account` 에서 로그아웃하면 가드가 로그인 화면으로 보냈다(홈으로 먼저 옮기고 끊는다). 768px 에서 로그인하면 헤더가 넘쳤다(닉네임 말줄임).

#### 4. 남은 한계

- **페이지가 없다.** 302켤레를 한 번에 받는다. 서버는 `_start` · `_limit` · `X-Total-Count` 를 지원한다.
- **세대 사이를 오가지 못한다.** 같은 라인의 이전 · 다음 세대를 묶는 `lineKey` 가 데이터와 API 에 있지만(`?lineKey=`) 상세 모달은 쓰지 않는다.
- **실측값을 보여 주지 않는다.** 공시값만 보이고, `measured*` 칸은 화면에 없다.
- **화면 시험이 자동이 아니다.** 계약 시험은 API 만 본다 — 화면은 사람이 브라우저에서 확인한다.

#### 5. 검증 항목

- 데스크톱 · 768px · 휴대폰 폭에서: 홈 → 카드 → 모달 → 리뷰 쓰기 → 닫기, 헤더가 넘치지 않는지.
- 비로그인으로 찜 · 리뷰 쓰기 → 로그인 → 같은 모달로 돌아와 쓰던 내용이 남는지.
- 값이 빈 신발의 모달에 "정보 없음"이 보이는지.
- `yarn build`(`tsc -b` 타입 검사 + vite)가 통과하는지.
