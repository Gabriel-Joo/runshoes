### 2.1 선택지

| 칸 | 선택지 | 저장 값 |
|---|---|---|
| 스펙 출처 | BITR · RSG · STORE · PR · WEB · MAN | 코드. WEB · MAN 을 고르면 URL 칸이 나온다(WEB 은 필수, MAN 은 선택 — 사람이 본 화면 주소) |
| (기존 값에만 보이는 출처) | DB · SX | 고를 수 없다. 기존 행에 그 출처가 있으면 회색으로 보이고, 값을 고치면 새 출처를 골라야 저장된다 |
| 중량 사이즈 | US M9 · M9.5 · M10 · M10.5 · M8.5 · 불명 | `M9` … · 불명 = NULL(지금 운영 값이 정확히 이 다섯 + NULL) |
| 발볼 | 좁음 · 보통 · 넓음 · **정보 없음** | 정보 없음 = NULL |
| 와이드 모델 · 카본 플레이트 | 있음 · 없음 · **정보 없음** | true · false · NULL |
| 가격 출처 | 공식몰 · ABC마트 · **크림** | 크림 = 발매가 → `price_kind` 정가. 기존 `다나와` 13행은 회색 표시(선택지에는 없다) |
| 성별 | 남성 · 여성 · 공용 | men · women · unisex |

### 2.2 저장 규칙(근거 없는 false 를 막는다)

- **와이드 모델을 "없음"으로 저장하려면 출처가 있어야 한다.** 출처 없이 없음 → 저장 버튼 아래 "없음은 근거가 있을 때만 — 출처를 고르거나 정보 없음으로" 2026-10-24 원칙(침묵으로 증명하지 않는다)
- 값을 바꾸면 그 칸의 출처를 다시 고르게 한다(옛 출처가 새 값에 붙지 않게). 가격을 바꾸면 날짜 · 출처도
- 값을 비우면 출처도 비운다
- 카본 플레이트는 출처 면제(지금 규칙) — 출처 칸 없음

## 3. 입력 제한

- 중량 · 드롭 · 스택하이트: 숫자와 소수점 한 자리(`/^\d{0,3}(\.\d?)?$/`) — 붙여 넣기도 같은 검사. `inputMode="decimal"`
- 가격: 정수만(`/^\d{0,7}$/`), `inputMode="numeric"`, 칸 옆에 천 단위 미리보기(199,000원)
- `type="number"` 는 쓰지 않는다 — e · + · − 가 들어가고 휠로 값이 바뀐다
- 서버도 지금처럼 숫자가 아니면 400(`Values`)

## 4. 드롭다운 화살표

`appearance: none` + 배경 화살표(`background-position: right 12px center`, `padding-right: 36px`). 모든 `<select>` 공통(`ShoeForm.css` · 정렬 바도 같은 규칙을 쓰면 같이).

## 6. 데이터 — 무엇이 바뀌나

### 6.1 스펙 출처를 DB 에 둔다 — V6

지금 DB 에는 칸별 출처가 없다(카탈로그 파일에만 있다). 관리 화면에서 고르려면 저장할 곳이 필요하다.

- **추천: `shoes.spec_sources` JSON 한 칸**(NULL 허용)
  `{"weight":{"code":"BITR","url":"https://…"},"drop":{…},"stackHeight":{…},"midsole":{…},"width":{…},"wideAvailable":{…}}`
  - 칸 12개(출처 6 + URL 6)보다 적고, 나중에 칸이 늘어도 마이그레이션이 없다. API 가 코드 · URL 형식을 검사한다(400)
- API 응답 끝에 `specSources` 추가(계약 테스트는 `--allow-added` 에 키 하나)
- 적재기가 카탈로그 `sources` 에서 코드를 만든다 — `todo.mjs` 의 `code()` 를 그대로(BITR · RSG · STORE · PR · MAN · DB · SX, 나머지 URL 은 WEB)
- **한 마이그레이션에 한 목적** — V6 = 스펙 출처, V7 = 데모 관리자(8절). V4 · V5 가 미뤄 둔 옛 칸 정리는 V8 로 밀린다(V4 · V5 주석은 "V6"이라 적혀 있다 — 이미 운영에 적용돼 고칠 수 없으니 V8 머리말에 그 사정을 적는다)

### 6.2 가격 출처 '크림'

`PRICE_SOURCES` 에 `크림`. V5 칸(VARCHAR(10))에 들어가 마이그레이션 없음. 화면 표시 "크림 2026/10/29 기준"(모달 그대로).

### 6.3 관리 화면 수정 vs 적재기

적재기는 카탈로그가 정답이라 DB 와 다르면 되돌린다. 화면에서 고친 값이 다음 적재에서 사라지지 않게:
- **추천: 적재 전에 `pull-admin.mjs` 가 운영의 사람 수정을 `decisions.json` 으로 가져온다** — 마지막 적재 기록(loads/)과 지금 운영 값이 다른 칸 = 사람이 화면에서 고친 칸. `by: "user", via: "admin"` 으로 적고, 빌드가 그 값을 쓴다
- 적재기 `--apply` 가 먼저 가져오기를 저절로 돌리고 진행한다(2026-10-30 사용자 결정, 로그에 "어드민 수정 N건을 decisions.json에 반영했다"와 칸마다 전 → 후). 옮길 수 없는 칸이 남을 때만 멈춘다

## 8. 데모 계정

### 8.1 일반 사용자 3개 — 무작위

- **풀: V3 시드 계정 30개(runner01~30@runshoes.test, 가상 인물)만.** 지금 가입자 33명 = 시드 30 + 관리자 1 + **실제 가입 2명** — 실제 가입자는 넣지 않는 것을 권한다: 카드를 누른 누구나 그 사람 이름으로 리뷰 · 찜을 할 수 있게 된다(사람의 계정이다)
- 화면을 열 때마다 서버가 3개를 골라 준다(닉네임 · 리뷰 수). 새 계정은 만들지 않는다
- 제한 없음 — 리뷰 · 찜 · 공감 모두 된다. 그 결과는 공개 화면에 그 시드 닉네임으로 남는다(시드 데이터가 방문자 손으로 바뀐다)

### 8.2 데모 관리자 1개 — 읽기 전용

- 계정 하나를 새로 만든다(V7): `demo-admin@runshoes.test` · 닉네임 "데모관리자" · role **`DEMO_ADMIN`**(VARCHAR(10)에 꼭 맞다, CHECK 를 넓힌다) · 비밀번호 없음(일반 로그인으로는 들어갈 수 없다)
- 관리 화면은 다 보인다(등록 · 수정 폼, 목록). 저장 · 삭제를 누르면 "데모 관리자 계정은 할 수 없습니다"
- **서버가 막는다**(화면만 막으면 API 로 우회된다): `requireAdmin()` 이 DEMO_ADMIN 에 403 `{"code":"demo_admin","message":"데모 관리자 계정은 할 수 없습니다"}`. 화면은 그 문구를 그대로 띄운다. 리뷰 · 찜도 막을지 — 추천: 막는다(읽기 전용)
- 지금 관리자 전용 읽기 API 는 없다(관리자 권한은 신발 쓰기에만) — 데모 관리자가 볼 개인정보가 없다

### 8.3 로그인 방식 — 비밀번호를 화면에 두지 않는다

- `GET /api/auth/demo-accounts` → 카드 4장(무작위 시드 3 + 데모 관리자)
- `POST /api/auth/demo {id}` → **데모 풀 안의 id 만** 일반 로그인과 같은 토큰을 준다(비밀번호 없이). 풀 밖(진짜 관리자 · 실제 가입자)은 400
- 이유: 시드 30개는 비밀번호 하나(`SEED_USER_PASSWORD`)를 같이 쓴다 — 화면에 넣으면 30개 모두의 비밀번호가 공개된다
- env `DEMO_LOGIN_ENABLED`(기본 꺼짐)로 켠다 — 끄면 카드도 API 도 없다
- 시도 제한은 로그인과 같은 RateLimiter, 활동 로그 `auth.demo_login`

3. **회원 탈퇴 = 소프트 삭제**(V9 `users.deleted_at`) — 로그인 차단, 리뷰는 "탈퇴 회원"으로 남김, 찜 삭제, 복구 없음, 같은 이메일 재가입 허용(새 계정 — 이전 리뷰는 안 돌아온다), 활동 로그 `user.withdraw`. 확인 화면 문구는 사용자 안 그대로
4. **리뷰 300자** — 운영 104건 최대 83자(2026-10-30 확인)라 그대로 진행. 등록 · 수정 양쪽, 입력 중 남은 글자 수
5. 마이페이지 — 왼쪽 목차(회원정보 수정 · 내 활동(내 리뷰 · 찜 목록) · 회원 탈퇴) · 오른쪽 본문(1 : 4.5), 맨 위 활동 요약(리뷰 · 찜 · 가입일)

구현하며 정한 것(설계 문서에 답이 없던 작은 것 — 되돌리기 쉽다):
- **마이그레이션 번호** — 한 목적에 하나: V6 스펙 출처 · V7 데모 관리자 · V8 신발 숨김 · V9 회원 탈퇴. V4 · V5 가 "V6"이라 적은 옛 칸 정리는 **V10** 으로(V6 머리말에 적었다)
- **와이드 "없음"의 출처 필수는 관리 폼만 본다** — 서버가 막으면 json-server 계약(spring-v3 W30 · W36 의 `wideAvailable:false`)이 깨진다
- **체험 계정 보호** — 시드 계정(runner01~30)과 관리자는 닉네임 변경 · 탈퇴 403. 체험 카드로 들어온 누구나 시드 이름 · 계정을 바꾸거나 지울 수 있게 되므로(시드 리뷰 작성자가 바뀐다). 데모 관리자는 회원 정보 수정도 403
- **탈퇴의 이메일 · 닉네임** — UNIQUE 를 비우려고 `withdrawn-<id>@runshoes.invalid` · `탈퇴-<id>` 로 바꾼다(원래 이메일은 남기지 않는다). 비밀번호 칸은 NULL 이 아니라 표식 `'!withdrawn'` — NULL 이면 기동 때 SeedPasswords(옛 이미지 포함)가 시드 비밀번호를 채운다. 데모 관리자도 같은 이유로 `'!demo'`
- **리뷰 공감(review_likes)은 탈퇴해도 남긴다** — 남의 리뷰의 공감 수가 바뀌지 않게. 찜만 지운다(사용자 문구가 찜만 말한다)
- **숨긴 신발의 id** — 행이 남으므로 새 신발 id 는 숨긴 것까지 센 max + 1(json-server 의 "지운 id 를 다시 쓴다"와 다르다 — 계약 W51)
- **숨긴 세대와 같은 라인 · 세대 · 성별** — DB UNIQUE 가 숨긴 행에도 걸려 500 이 되므로 409 `hidden_generation`("되살려 주세요")
- 체험 로그인 시도 제한 — 같은 IP 15분 30번(비밀번호가 없는 길이라 성공을 센다)
- 계약 기준선의 계정 id — 데모 관리자가 32 를 가져가 계약 가입 계정이 33(옛 기준선과의 차이 6건, docs/API_CONTRACT.md 2.5)
