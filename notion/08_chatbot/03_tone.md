# 08-03 말투와 생성 검사

챗봇의 답 문장은 언어 모델(글을 읽고 이어지는 글을 지어내는 AI)이 짓는다. 이 편은 어떤 모델을 쓰는지, 그 모델에게 어떤 말투를 시키는지, 그리고 모델이 쓴 글을 그대로 내보내지 않고 무엇을 걸러 내는지를 다룬다.

## 어떤 모델을 쓰나

답을 짓는 모델은 이미 호스트에서 돌던 gemma4:e4b를 그대로 쓰고, 새 모델을 받지 않는다. [docs:09_chatbot_rag.md:347] 그래픽카드 메모리 16.3GB 가운데 13GB를 이미 쓰고 있어(2026-11-10), 7B급 모델을 하나 더 올리면 같은 그래픽카드를 쓰는 다른 서비스(펫퍼민트)가 학습할 때 메모리가 모자라 멈춘다. [docs:09_chatbot_rag.md:349]

질문을 갈래로 나누는 라우터(질문을 받아 어느 갈래로 보낼지 정하는 단계)도 같은 모델을 쓴다. 작은 모델은 정해진 꼴의 JSON(프로그램끼리 주고받는 데이터 꼴)을 내는 데 불안할 수 있어서, 모델이 함수를 골라 부르게 하는 기능에는 기대지 않고 JSON으로만 답하게 해서 받는다. 라우터 모델은 질문마다 한 번 부르되, 규칙으로 갈래가 정해지면 규칙을 따르고 규칙이 정하지 못할 때만 모델의 답을 쓴다. [docs:09_chatbot_rag.md:351]

## 말투

화자는 러닝화 담당자다. 해요체로 말하고 이모지를 쓰지 않는다. 경쾌하고 친근하게, 러닝을 좋아하는 사람의 말투로 쓴다. [docs:09_chatbot_rag.md:355-358] 느낌표는 인사, 마무리, 격려에만 쓰고 숫자나 비교의 결론에는 쓰지 않는다. 통증이나 거절을 말하는 자리에서는 톤을 한 단계 낮춘다. [docs:09_chatbot_rag.md:359-360]

쓰지 않는 말도 정해 두었다. "전문가"라고 스스로 부르지 않는다. 담당자이기 때문이고, 전문가라면서 통증 질문에 전문의를 권하면 앞뒤가 맞지 않기 때문이다(→ 「용어, 통증 질문, 신발 이름」). "완벽한 선택이세요" 같은 치켜세우기도 쓰지 않는다. "죄송합니다만"을 되풀이하지 않는데, 거절이 사과가 되어서는 안 된다고 봤다. [docs:09_chatbot_rag.md:364-366]

## 거절할 때

거절할 때는 상황마다 정해 둔 문구를 쓴다. [docs:09_chatbot_rag.md:370-375]

| 상황 | 문구 |
|---|---|
| 없는 신발 | "그 모델은 이 사이트에 등록되어 있지 않아요. 비슷한 모델로 찾아볼까요?" |
| 없는 용어 | "이 사이트에서는 다루지 않는 용어예요. 대신 OO은 설명해드릴 수 있어요." |
| 범위 밖 | "저는 러닝화 안내를 담당하고 있어서 그 질문은 도와드리기 어려워요. 대신 신발 쪽은 무엇이든 편하게 물어보세요!" |
| 근거 없음 | "그 부분은 등록된 정보에 없어서 확인이 어려워요." |

네 문구에는 원칙이 둘 있다. 거절로 끝내지 않고 할 수 있는 것을 하나 내놓는다. 그리고 "제가 모른다"가 아니라 "등록되어 있지 않다"로 말한다. [docs:09_chatbot_rag.md:377] 없는 신발을 물은 기록은 관리 화면에 보이고, 다음에 모을 신발의 후보가 된다(→ 「관리 화면」). [docs:09_chatbot_rag.md:379]

## 예시가 규격서다

말투를 글로 설명하면 모델이 매번 다르게 해석한다. 그래서 예시 답변 여섯 개를 모델에게 주는 글(프롬프트)에 고정해 두었다. 인사와 없는 신발, 범위 밖 거절, 통증, 무게 비교, 비교 결과, 추천이고, 사람이 직접 썼다. 이 예시가 말투의 규격서 노릇을 한다. [docs:09_chatbot_rag.md:381] 여섯 개를 늘 다 주지는 않고 갈래마다 맞는 것을 골라 준다. 경험과 후기 갈래에는 예시를 주지 않는다. [docs:09_chatbot_rag.md:382]

## 생성 검사

모델이 쓴 글은 바로 나가지 않는다. 우선 숫자는 모델이 쓰지 않는다. 무게, 가격, 리뷰 건수는 코드가 데이터에서 그대로 넣고 모델은 그 둘레의 말만 다듬는다. [docs:09_chatbot_rag.md:28] 스펙, 비교, 추천 갈래에서는 코드가 먼저 답을 만들어 모델에게 참고로 준다. [docs:09_chatbot_rag.md:620] [docs:09_chatbot_rag.md:641]

모델이 쓴 답에 쓰지 않기로 한 말이 나오면 검사가 그 답을 버리고 코드가 만든 답으로 바꾼다. 예를 들어 "전문가"가 나오면 사전 원문을 옮긴 짧은 코드 답이 나간다. [docs:09_chatbot_rag.md:647] 대화 한 턴마다 이렇게 코드 답으로 바꿨는지를 기록에 남긴다(→ 「운영 장치」). [docs:09_chatbot_rag.md:468]

평가는 같은 기준을 문항 전부에 건다. 답 속 숫자를 API의 원래 값과 하나하나 맞대고, "~때문입니다", "증상", "치료" 같은 진단으로 읽히는 표현과 "러너들이", "실제 사용자", "많은 사람들" 같은 쓰지 않기로 한 말을 찾는다. 몇 개를 골라 사람이 읽는 대신 전부를 자동으로 본다(→ 「평가와 바꿔 온 길」). [docs:09_chatbot_rag.md:697] [docs:09_chatbot_rag.md:700-701] [docs:09_chatbot_rag.md:704]

## 무엇이 어려웠나

처음 설계안의 말투는 반말에 이모지 한두 개였다. 고른 것은 해요체, 이모지 없음, 러닝화 담당자다. [docs:09_chatbot_rag.md:570] 화자를 "전문가"가 아니라 "담당자"로 둔 까닭은 통증 질문에서 드러난다. 이 챗봇은 몸에 관한 질문이면 맨 앞에 전문의 안내를 두는데, 전문가라면서 전문의를 권하면 앞뒤가 맞지 않는다. [docs:09_chatbot_rag.md:364] [docs:09_chatbot_rag.md:300]

## 알려진 한계

- 스펙, 비교, 추천 갈래의 답은 코드가 만든 답과 거의 같다. 코드 답을 참고로 주니 모델은 말투만 조금 다듬고, 예시의 말투가 덜 묻어난다. 숫자 정확도와 맞바꾼 것이다. [docs:09_chatbot_rag.md:641]
- 쓰지 않기로 한 말에 걸려 코드 답으로 바뀌면 틀린 말은 없지만 답이 짧고 딱딱하다. [docs:09_chatbot_rag.md:647]
- 이 서비스 전체에 걸린 한계와 조건은 → 「알려진 한계」 한 편에 모았다.

## 용어 풀이

- 프롬프트: 언어 모델에게 일을 시킬 때 함께 주는 지시와 예시의 글
- 해요체: "~해요", "~이에요"로 끝나는 부드러운 존댓말
- 코드 답: 언어 모델을 거치지 않고 코드가 데이터로 바로 만든 답
